# Metadata APIs: throttling, 503s, 403s and read lag

## Symptom

- MusicBrainz answers `503 Service Temporarily Unavailable`, or a message that requests are throttled because the application has not identified itself.
- An entity you just created on MusicBrainz is not found by the next search, so the script creates it again.
- A Spotify fetch stalls after a few dozen items with no output, then crawls.
- A web endpoint returns `403` with an HTML block page (often Cloudflare) instead of JSON, while the same URL works in a browser.
- A login session for website edits expires in the middle of a long run.

## Why it happens

- MusicBrainz allows about one request per second per client and answers 503 when pushed. It throttles clients without a descriptive `User-Agent`.
- Its read side trails an edit by one to four minutes, search longer.
- Spotify returns `429` with `Retry-After`; output buffered by Python hides the waits.
- Sites behind bot protection reject scripted requests. Some endpoints need a per-request code generated by the site's own JavaScript.
- Browser sessions behind a website login last hours, not days.

## How to check

```sh
curl -s -o /dev/null -w '%{http_code}\n' -A 'my-tool/1.0 (contact-url)' 'https://musicbrainz.org/ws/2/artist?query=some%20artist&fmt=json'
curl -sI <url> | grep -iE '^(HTTP|retry-after|server|cf-)'
```

## Fix

- Send a descriptive `User-Agent` with a contact URL, space requests at one per second, and cache identical reads for the life of the process.
- Treat repeated 503s as an outage: wait it out with backoff, pause the batch, and rerun later. Make every step idempotent so a rerun skips finished work.
- Remember ids of entities you created (a small "pins" file) and use them before any search.
- On `429`, sleep for `Retry-After` plus a little, log each wait, and run with `python -u`.
- When a site blocks scripts, use its official API with client credentials instead of scraping. Do not try to reimplement anti-bot codes.
- Check every login and token before a long run, and stop at once with a clear message when a request is redirected to a login page.

## How to prevent

- Run a health check (reachability, token expiry) at the start of every batch.
- Never let a write step run without an explicit switch, and validate input files before planning, so a typo stops the run rather than a half-done batch.
- Remember that some edits are not applied at once (removals on MusicBrainz go to a 7-day vote for most editors).

## Which tool helps

Planned. Private plugins can wrap these services; secrets come in through `homelab secrets` (see `secrets-and-unv.md`).
