# Changelog

## Unreleased
- **Bundled scripts ship in the wheel.** They moved to `src/homelab/scripts/` and `scripts_dir` defaults to that folder, so a pip install has every bundled script. Tests pin `scripts_dir: scripts` in their own temp config.
- **`journal` action (plugin API 1.4.0):** one action that carries thousands of moves from a JSON-lines file (`journal_action(ctx, moves, describe)`). The engine streams it, writes each finished move to its own journal, and `undo` replays that journal backwards; a run that dies half way can still be undone. Plans are checked against the declared writes and the files, as with `move`.
- **`jellyfix` plugin:** the jellyFix tool as a bundled plugin (jobs `rename`, `verify`, `prune`); renames are engine moves, so they are reviewed, journalled and reversible, and subtitles follow their video. A plugin that raises `ValueError` while planning now gives an `invalid` error (exit 10).

- **Autonomy and inventory.** `policy` levels (deny, plan, ask, auto) with glob rules, `homelab policy`, `homelab pause` and `resume`, scheduled pipelines apply only `auto` steps (`HOMELAB_SCHEDULED`), `inventory` names for stacks (`stack=NAME` instead of a path). Plugin API 1.3.0: `ctx.named()`, and `apply_action` and `undo_action` on `@script`.
- **Tamper-evident audit.** Hash-chained `audit.jsonl`, `homelab audit` and `homelab audit --verify`, and `docs/VERIFY.md`.
- **Reversible `compose_update`:** image ids are recorded before the pull, and `undo` retags them and recreates the services.
- **`homelab report` and `homelab attention`:** snapshot diff with typed kinds (gone, new, replaced, state, restarts, disk, skipped) and a ranked list of what needs attention.
- **Long runs:** `apply --detach`, `homelab cancel`, `running` status, interrupted-run detection.
- **Service scripts (read only):** Radarr, Sonarr, Prowlarr and qBittorrent status, queue, indexer and torrent views.
- **Onboarding:** `homelab skill [--install]`, `homelab demo`, `llms.txt`, and Claude, Codex and Gemini plugin manifests.

- **First bundled plugin: `nextcloud`** (`plugins/nextcloud`, package `homelab-plugin-nextcloud`, entry point `homelab.plugins`). `put` and `delete` over DAV (CalDAV and CardDAV included) save a copy of what is there before replacing or removing it, and `undo` restores it; an undone creation is saved to `removed/` first, because contacts have no trash. The app password comes from `NEXTCLOUD_APP_PASSWORD`.
- `ctx.path("state")`: each plugin gets its own folder under `state/plugins/<name>/` for journals and saved copies.
- Script `import_repo_history`: brings an old repository's full history (local-only `history/full/NAME/*` branches) and notes into the project, with an index.

- **Docker scripts.** `docker_ps` (read only), `compose_restart` and `compose_update` work with any Docker Compose v2 stack through the `docker` CLI.
- **Leak audit.** `tools/leak_audit.py` and a `pre-push` hook check every unpushed commit for private paths, the machine's home folder and host name, secret-shaped values and the owner's own patterns, and refuse `history/*` branches. Maintenance tools moved from `scripts/` to `tools/`, so `scripts/` holds only engine scripts.
- **Docs.** `docs/PUBLISHING.md` (build, publish, release, history import, leak recovery), `docs/ECOSYSTEM.md` (what it can do and what it supports, with the status of each item), and a build-and-publish tutorial in `AGENTS.md`.

- **Scripts system.** `@script` and `script_exec` in `homelab-plugin-api` 1.2.0: a one-off becomes a one-job plugin with plan, apply, undo, audit and secrets. `homelab scripts` finds and lists them, `script-new` scaffolds one, `plan --set KEY=VALUE` sets options (stored with the run). A basic nudge (`when`, `before`, `after`, `avoid`) shows in `describe`, `plan` and `apply` as `data.nudge`, `data.ask_owner` and `data.next`; the engine calls no model. Bundled example: `scripts/clean_junk_files.py`.
- **Sample environment.** `.env.example` is generated by `tools/gen_env_example.py` from the engine variables and the secrets that bundled plugins declare, and checked in CI. `docs/UNV.md` is the UnENVerse guide; `secrets.entries` accepts `entry:field`.

- **CLI contract for agents.** Every command takes `--json` and answers `{ok, command, data}` or `{ok:false, error:{code, message, details}}`; ten typed exit codes; `describe` prints the whole contract (generated from the parser table); `--dry-run` on apply, undo and run; `--limit` with a `left_out` count; `--yes` for non-terminal apply and undo; run lookup by id, unique prefix or `latest`; bare job names; near-match suggestions and ambiguity candidates; new commands `describe`, `status`, `secrets`, `show` and `completions`; an append-only `state/audit.jsonl`.
- **Secrets.** `secrets` block in `homelab.yaml`: UnENVerse (recommended, the engine re-executes under `unv exec`) with a `.env` fallback that must be mode 600. `ctx.secret_ref()` placeholders are filled at apply time; values that reach a plan are scrubbed from the ledger and output. `homelab-plugin-api` 1.1.0.
- Agent files: `skills/homelab-ops/`, `docs/CLI.md`, `docs/SECRETS.md`, example permission rules.

- Engine with plan, apply and undo: every run is a ledger record, applied exactly as reviewed, and reversible. Nothing is ever deleted; removals are moves into a quarantine folder.
- Plugin contract (`homelab-plugin-api` 1.0.0): manifest with declared permissions, jobs that return plans, optional plugin-defined actions with undo.
- Plugin discovery from installed entry points (`homelab.plugins`) and a private `custom/` folder, with broken plugins isolated and reported.
- Three YAML config files (`homelab.yaml`, `plugins.yaml`, `jobs.yaml`) with checked-in JSON schemas.
- `homelab` commands: `plugins`, `doctor`, `plan`, `apply`, `undo`, `runs`, `run`, `schedule`, `plugin-new`, `schema`.
- Public trust files: security policy, governance, threat model, assurance case, support policy, Scorecard, CodeQL, OSV, gitleaks and zizmor workflows, a protect-main ruleset, signed releases with SBOM and provenance, weekly Atheris fuzzing.
