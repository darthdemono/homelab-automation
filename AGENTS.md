# AGENTS.md

Guidance for any coding agent or contributor working in this repository. This file is generic and public: personal instructions never go here.

**First, if `Agents/Index.md` exists, read it.** It lists the owner's personal instruction files, which live in the gitignored `Agents/` folder. If it does not exist, ignore this paragraph: everything you need is below.

## What this is

A small plugin engine for homelab automation. Every change is planned first, stored in a run ledger, applied exactly as reviewed, and reversible. See [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md) for the invariants and [`CONTRIBUTING.md`](CONTRIBUTING.md) for the workflow.

## Layout

| Path | What it holds |
| --- | --- |
| `src/homelab/` | The engine: config, registry, runner (plan, apply, undo), conformance, schedule, scaffold, CLI |
| `packages/homelab-plugin-api/` | The public plugin contract (depends only on pydantic) |
| `plugins/` | Bundled, general-purpose plugins, one package each |
| `custom/` | Private plugins. Gitignored: never commit anything here |
| `Agents/` | Personal instruction files, listed in `Agents/Index.md`. Gitignored |
| `config/` | Example config (`*.example.yaml`). Real config is gitignored |
| `schemas/` | JSON schemas of the config files, generated by `tools/gen_schemas.py` |
| `skills/` | Agent skill for operating the homelab through the CLI |
| `tools/` | Maintenance tools: schema and env-sample generators, the leak audit |
| `fuzz/` | Atheris fuzz target for config parsing |
| `tests/` | pytest suite with a 85 percent coverage floor |

## Commands

```sh
uv sync
uv run pytest
uv run ruff check . && uv run ruff format --check .
uv run python tools/gen_schemas.py --check
uv run homelab --help
```

## Agent workflow

The CLI is the whole interface; there is no server to connect to. Run `homelab describe` once. For a task, `homelab scripts <words>` first (a one-off may already exist, with a nudge telling you when to use it and what to check). Then: `plan`, show the plan to the owner, ask, `apply --yes`, `show` to verify. Read exit codes (see [`docs/CLI.md`](docs/CLI.md)), use `--json`, and keep output small with `--limit`. A ready-made skill is in `skills/homelab-ops/`, and permission rules for Claude Code are in `docs/agent-permissions.example.json`. Secrets come from UnENVerse (`unv`, recommended) or a 600-mode `.env`: see [`docs/SECRETS.md`](docs/SECRETS.md). Never print or request a secret value.

## Build, publish, and keep local files local

For a local session working on this repository. Full detail: [`docs/PUBLISHING.md`](docs/PUBLISHING.md).

1. **Build and check** (the same steps CI runs): `uv sync`, `uv run pytest -q --cov=homelab --cov-fail-under=85`, `uv run ruff check . && uv run ruff format --check .`, `uv run python tools/gen_schemas.py --check`, `uv run python tools/gen_env_example.py --check`, `uv lock --check`, and `uv build --all-packages` for the sdist and wheel.
2. **`main` is protected.** No direct pushes and no force pushes. Cut a branch from `origin/main` (`git fetch origin && git switch -c <name> origin/main`), commit in small topical groups, push the branch, open a pull request, and wait for the `CI result` check. Merging is squash or rebase.
3. **Before every push run `python tools/leak_audit.py`** and install the hooks once (`git config core.hooksPath .githooks`; `pre-push` runs the audit). It blocks private paths (`Agents/`, `custom/`, real `config/*.yaml`, `state/`, `.env`, handoffs, research), the machine's home folder and host name, secret-shaped values, and anything in `Agents/leak-patterns.txt`. It never prints a matched value. If it reports something, fix the commits, do not bypass the hook.
4. **Never** `git push --all` or `--mirror`, never push a `history/*` branch (the hook refuses it), and never commit anything from the gitignored folders listed in [`docs/PUBLISHING.md`](docs/PUBLISHING.md).
5. **GitHub already has** the CI, CodeQL, Scorecard, Security audit and Fuzz workflows, a `protect-main` ruleset, Dependabot (weekly, 7-day cooldown), secret scanning with push protection and private vulnerability reporting. A release is the manual **Release** workflow from `main` after the version and changelog are bumped in a pull request.
6. **History of an old repository** has two forms. Full and local only: `homelab plan import_repo_history --set repo=PATH --set name=NAME` fetches every branch into `history/full/NAME/*` and copies its notes next to the project; the pre-push hook refuses those branches. Public: a filtered, code-only import into `history/<name>` (recipe in `docs/PUBLISHING.md`), merged on a pull-request branch with `--allow-unrelated-histories` together with the plugin's `pyproject.toml`.

## Rules

- Keep the invariants: plan first, apply only a stored plan, undo anything, never delete (move to quarantine), commands are argument lists, secrets are environment variable names.
- A plugin declares what it may touch in its manifest. Do not widen a manifest to make a test pass.
- A bug fix needs a regression test. Change a config model, then regenerate `schemas/`.
- Keep personal paths, account names and library contents out of tracked files. Personal tools are private plugins in `custom/`.
- Do not commit, push or change repository settings unless the maintainer asks in the session.
- Pin every GitHub Action by full commit SHA with a version comment, and keep workflow permissions minimal.
- Local notes live in `Handoff/` and `Research/`, which are gitignored. So are `state/` (ledger, quarantine, per-plugin journals under `state/plugins/<name>/`) and the real config files.
